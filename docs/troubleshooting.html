LightSuite Neuroglancer: troubleshooting

How to check that a dataset opens correctly, and what to do when region names, statistics, the viewer or the installation do not work. See also the installation guide and the user guide.

1. Checklist for a proper run

Go through this once per new dataset (or new PC). Most problems come from one of these points.

  • The results folder is complete. It contains volume_registered\sample_space\sample_space_manifest.json and the TIFFs listed in it, plus stats\ and the config_*.yaml. Copy the whole folder, not only some files.
  • The atlas is reachable. The sample's config_*.yaml has atlas.atlas_dir pointing to an atlas folder on this PC, or you pass --atlas-dir. A folder holding several atlases works, e.g. --atlas-dir D:\LIGHTSUITE\atlas. See section 3.
  • The terminal output looks right (section 2): the expected atlas in region names from:, no WARNING, statistics found.
  • The registration looks right in the viewer: the outlines follow the anatomy (user guide, section 3).
  • Enough resources: 3–4 GB free disk and about 8 GB RAM for a 20 µm brain, results on a local disk for the first conversion.

2. Read the terminal output

The first conversion prints a short report. This is the quickest way to see if something is wrong. Example for a Perens brain:

Converting D:\...\8_DNF_atlased -> D:\...\8_DNF_atlased\neuroglancer
  grid (331, 671, 671) (x,y,z), voxel [20.0, 20.0, 20.0] um, channels ['ch1', 'ch2']
  region names from: atlas region table (D:\LIGHTSUITE\atlas\perens_20um\ARA2_annotation_info.csv)
  WARNING: the annotation volume is uint16 (max 65535), but the atlas has 128 region IDs above that ...
  region statistics: atlas_median_intensity_ch1_right, ...
  level 'regions': 615 regions
  ...
Viewer (with region search and channel LUTs): http://127.0.0.1:50893/lightsuite/
LineCheck
grid … voxel …The voxel size is the registration resolution (e.g. 20 µm). All channels you expect are listed.
warning: channel N file not foundA channel TIFF is missing. It is skipped. Copy it back into the results folder.
region names from:Should name your atlas file. sample stats/region_stats.csv or label numbers only means the atlas was not found (section 3).
WARNING: the annotation volume is …The annotation itself is damaged (section 4).
region statistics: none foundNo LightSuite statistics tables (section 5).
Using cached conversionNothing changed since the last run. Use --reexport to convert again anyway.

On later runs the report is not printed again, because the cached conversion is reused. To see it again, run once with --reexport.

3. Region names

Names are numbers, or many regions are “label N (not in atlas)”

The tool takes region names from the first source it finds, in this order:

#AtlasFile it looks for
1Spinal cord (Fiederling)Atlas_Regions.csv
2Allen CCFparcellation_to_parcellation_term_membership.csv
3Perens / Gubra LSFMARA2_annotation_info.csv
4BrainGlobe atlasesstructures.json in ~/.brainglobe or %BRAINGLOBE_DIR%
5The sample's own statisticsstats\region_stats.csv: names only for the regions LightSuite measured
6nonebare label numbers

Files 1–3 are searched in: --atlas-dir, the config's atlas.atlas_dir (both with their subfolders), and ~/atlases/*.

Fix:

  1. Check the region names from: line (section 2).
  2. Make the atlas folder reachable, in one of two ways:
    • Edit the sample's config_*.yaml. Configs written on the analysis server often hold a Linux path or a placeholder such as /path/to/allen_ccf_10um: 
      atlas:
  provider: perens
  atlas_dir: D:\LIGHTSUITE\atlas\perens_20um     # or D:\LIGHTSUITE\atlas
      The next run detects the change and converts again.
    • Or, without editing anything, run once with the folder (the conversion is redone because the option changed): 
      lightsuite-neuroglancer D:\IMAGE_REG_DATA\brain8_analysed\8_DNF_atlased --atlas-dir D:\LIGHTSUITE\atlas
      Pass --atlas-dir on every later run too, otherwise the tool converts again without it.
  3. If you add atlas files to a folder that was already searched, nothing triggers a new conversion. Run once with --reexport.

With the atlas found, a few labels can still be “not in atlas”. If the terminal shows the WARNING: the annotation volume is uint16 line, see the next section. Otherwise these are values in the annotation that the atlas does not list (often a different atlas version than the one used for registration).

The wrong atlas is used

The first matching file wins, and folders whose name contains the config's atlas.provider (e.g. perens) are tried first. An Allen file is used only when the provider is allen or unknown. Give the exact atlas folder with --atlas-dir to be sure.

The hierarchy levels look odd

With the Perens, spinal cord and BrainGlobe atlases, levels are counted from the root of the atlas tree (depth 3, depth 2, …), so each layer cuts the tissue at one depth. Large regions can appear at the same level as their parents. This is expected. The regions layer always has the finest labels.

4. Labels corrupted in the annotation

WARNING: the annotation volume is uint16 (max 65535), but the atlas has 128 region IDs above that
(e.g. 182305689). Those regions were corrupted when the annotation was saved, which is probably why
23 labels are 'not in atlas' (1216, 2656, 12096, 12160, 12288, 14144, ...).

What it means. Allen-based atlases (Allen CCF, Perens) have region IDs up to about 600 million, e.g. VISrl6b = 312782624. The registration pipeline saved the annotation warped onto the sample (annotation_in_sample_20um.tif) in a type that cannot hold them, after passing it through 32-bit floating point. The result:

  • about 128 regions (e.g. VISa, VISli, VISrl, VISpor, ProS, the LGd subregions, SSp-un, the interpeduncular nuclei) are merged into a few meaningless labels. One label can hold up to 8 regions;
  • a corrupted ID can also land on a real, smaller ID, and then a region is silently labelled as another one;
  • LightSuite's own statistics do not include these regions.

The viewer cannot repair this, because several regions share one corrupted value. The fix is in the registration pipeline: write the warped annotation as uint32, and warp it with nearest-neighbour interpolation and an integer output type, so that IDs are never converted to floating point. Then re-run the registration export and the statistics.

Until it is fixed, do not use the affected regions (and the statistics of their parent regions) from this brain. The rest of the annotation is not affected.

6. Errors that stop the tool

MessageCause and fix
No LightSuite results found in …No volume_registered\sample_space\sample_space_manifest.json in the folder or the 4 levels below it. Choose the registration output folder.
Not a folder: …The path does not exist. Put paths with spaces in quotes.
No folder selected. / Invalid choice.The folder picker was closed, or a wrong number was typed when several results were found.
Annotation volume (annotation_path in the manifest) not found.The manifest points to a path on another machine (e.g. /media/gbm/...) and the file is not in the results folder either. Copy the annotation TIFF into volume_registered\sample_space\ or the results folder.
Shape mismatch: … vs annotation …A volume in the manifest has a different size from the annotation, usually files from two different registration runs. Re-export the registration, or remove the stray file.
Traceback … MemoryErrorNot enough RAM. Close other programs, or use --no-meshes (section 9).
PermissionError / Access is deniedUsually a file open in another program (e.g. Fiji) or a sync tool such as OneDrive. Close it, or write elsewhere with --out.
OSError: [Errno 98/10048] address already in useThe port given with --port is taken, e.g. by another viewer. Leave out --port or choose another.

7. Zoom stack errors (--zoom)

MessageCause and fix
expected one folder with multires_regopts.json, found 0 (or 2+)Pass the multires results folder itself (the one with multires_regopts.json), not its parent.
pair manifest … not found / ROI TIFF for channel … not foundFiles of the multires run were moved and are not in the expected subfolders (converted\). Copy the whole multires folder, and keep the raw ROI TIFFs at their recorded path or next to the folder.
elastix TransformParameters files not found / initial transform … not foundThe elastix_roi_to_overview folder is missing or incomplete.
elastix 'BSplineTransform' is not affine …The ROI-to-overview registration has a B-spline stage. It cannot be shown as one transform. Use a rigid/affine ROI registration.
HowToCombineTransforms … is not supportedOnly composed elastix transforms are supported.
--zoom needs …regopts.jsonThe atlas results folder must contain regopts.json.
The zoom's overview stack … is not the stack the atlas registration usedThe multires run used a different overview stack (size or voxel size) than the atlas registration. Use the multires results of the same brain and the same overview.
channel … ROI geometry differs from the reference channelThe ROI channels have different sizes or positions. Each must be a separate multires run.
expected a 3D stackThe ROI TIFF is not a single 3D stack (e.g. one file per plane or a multi-channel file).
The ROI sits on the wrong anatomyThe tool only applies the saved transforms. Check the multires landmarks and elastix result.

9. Speed, memory and disk

  • First run is slow: building the 3D meshes takes most of the time. Use --no-meshes for a quick look. Copy the results to a local SSD; network drives are much slower.
  • Converts again every time: something in the results folder changes between runs (e.g. a sync tool touching files), or you alternate between runs with and without --no-meshes or --atlas-dir. Each different set of options causes a new conversion. Updating the tool also causes one new conversion.
  • Memory: about 8 GB for a 20 µm brain. Zoom stacks are read fully into memory: a large ROI needs RAM at least the size of its TIFF.
  • Disk: 3–4 GB per brain in <results>\neuroglancer\, and about 1.15× the TIFF size per zoom stack. These folders can be deleted at any time.
  • Read-only results folder: the converted data goes to %LOCALAPPDATA%\lightsuite-neuroglancer\ (Linux/macOS: ~/.cache/lightsuite-neuroglancer/). Clean it from time to time.

10. Installation and versions

The tool is tested with fixed versions of its Python packages. Ranges are set in pyproject.toml, and the exact tested versions are in view_in_neuroglancer.py.lock. Neuroglancer in particular is pinned to one version (2.41), because newer versions can change things the viewer relies on.

ProblemFix
uv or lightsuite-neuroglancer not recognizedReopen the terminal after installing. Run uv tool update-shell once. See the installation guide.
“Microsoft Visual C++ 14.0 or greater is required” (while building pyyaml, imagecodecs, …)The Python version is too new for some packages (no ready-built versions yet), so uv/pip tried to compile them. Use Python 3.12: run_viewer.bat does this automatically. Otherwise add --python 3.12 to uv run or uv tool install, or create the conda env with python=3.12. Don't install Visual C++ for this.
“does not appear to be a Python project”The folder has no pyproject.toml: it is an old or partial copy. Download the whole repository again.
Download fails on the first runNo internet or a proxy. Set HTTPS_PROXY before running.
Errors appeared after an update, or the environment seems brokenReinstall cleanly: 
uv cache clean
uv tool install --reinstall git+https://github.com/YCabara/lightsuite_neuroglancer.git
When running from the folder (uv run view_in_neuroglancer.py), uv uses the exact versions of the lock file. uv cache clean is enough.
pip reports a conflict (e.g. neuroglancer, numpy)Another package in the same environment needs other versions. Install the tool in its own environment (uv tool install, or a separate conda env).
Which version am I running?lightsuite-neuroglancer --version

11. Reporting a problem

If none of the above helps, send to the maintainer:

  1. the version (lightsuite-neuroglancer --version) and the operating system;
  2. the exact command you ran;
  3. the full terminal output of a run with --reexport (copy the text; a screenshot cuts long lines);
  4. for viewer problems: a screenshot and the browser name and version;
  5. the sample_space_manifest.json and config_*.yaml of the dataset (small text files). Do not send the TIFFs unless asked.
